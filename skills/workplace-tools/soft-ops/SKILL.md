# soft-ops

把零散桌面软件任务做完，并把可复用的事实写回记录。网页平台归 `web-ops`，这里管本机软件、客户端、配置与插件迁移。Claude Code/Codex 共用；优先当前宿主已有的 CLI、配置文件和原生自动化，不依赖特定宿主的工具名。

## 执行顺序

1. 先读已有软件记录，核实安装版本、运行进程、真实配置路径和用户当前选中的配置。相似界面不代表配置、插件 ABI 或动作 ID 兼容。
2. 优先软件自带 CLI、受支持配置格式、导入转换器和原生系统自动化。确需网页才开浏览器，不为桌面任务启动无关浏览器或本地服务。
3. 修改前检查目标并备份。备份和测试产物放 `${SOFT_OPS_WORK_DIR}/<软件>/<时间>/`（未设置时用系统临时目录），限制含隐私备份的权限；密码库、token、证书、私钥、完整个人配置不入 skill 或 git。
4. 用户已授权直接改本地设置时，备份完就改，不反复弹「导出设置」。进程持有的 SQLite/localStorage 必须先正常退出软件再改，不强杀丢失未保存内容。对话框消失先看真实窗口/进程，不拿旧控件继续输入。
5. 格式转换按目标真实 schema 和 parser 验证。快捷键按动作语义映射，不按相同按键猜动作；保留显式空列表解绑，分别处理多段 chord、鼠标、上下文和原生编辑器绑定。每条来源都标明迁移/部分迁移/不支持。
6. 插件先核对运行时和 API。JAR 插件不等于 WASM 插件；内建功能覆盖只能标「替代」，不计为原插件安装成功。宏、模板变量、语法上下文无法等价时保留原文和原因，不写无效表达式假装成功。
7. 合并时保留目标已有设置和无关 storage。校验目标文件未被并发修改，写后回读；重启后在真实设置页核对。不以文件存在、解析通过或命令退出 0 代替应用生效。
8. 收尾更新该软件的记录：现象、根因、做法、命令、验证证据、限制与回滚；没有证据的结论写「未验证」。不 commit/push，除非用户明确要求。

## 后台 GUI 操作（不打扰用户）

用户要 AI 操作某个桌面软件、又不想被抢鼠标和焦点时，按 [background-gui.md](references/background-gui.md) 选路线：

- 有业务 API 或 CLI：直接调，不碰界面。
- Electron 应用且 `--inspect` 未被 fuse 关闭：开独立 user-data-dir 的第二实例，经 Node inspector 把窗口设为透明、不可聚焦（不用 `hide()`）并脚本操作页面，与用户实例完全分开。
- 其他原生应用，或要在用户正在用的同一窗口里操作：`cua-driver` MCP（辅助功能后台投递，不移动光标、不抢焦点）。
- 要彻底隔离整机：macOS 虚拟机（cua `lume`、`tart`）。

用户要自己双开某个软件（如登录第二个账号）时，按同一 reference 的「双开」节：Electron 应用用 `open -n` + 独立 `--user-data-dir`；要在「应用程序」里点开就跑 `scripts/dual-open/make-launcher.sh <源 .app>` 生成启动器（防重复启动、沿用原图标），要藏副本的 Dock 图标加 `DUAL_HIDE_DOCK=1`。任意软件启动不显示 Dock 图标，按同一 reference「任意软件启动时不显示 Dock 图标」节选路线（Electron 走进程内改；其他软件改副本的 `LSUIElement`，有签名和更新限制）。

## 记录规则

- 一个软件一份 reference；一次性任务也写进对应 reference，不另建散落说明或独立 skill。
- 重复且已跑通的确定性转换才放 `scripts/<软件>/`。默认 dry-run，明确 `--apply` 才写真实配置；路径用环境变量覆盖加绝对路径默认值。
- 记录软件版本与日期、源/目标、选中的配置、备份位置、变更清单、实际成功数量、不支持项、独立回读结果和恢复步骤。
- 完整个人数据、源码 checkout、大报告、截图与备份留在工作目录；reference 只写路径与必要统计，不复制秘密。
- 说「后台运行」前核实进程与进度，不把异步任务启动当完成。
