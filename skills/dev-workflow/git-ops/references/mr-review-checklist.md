# MR 评审清单

按顺序看，前面的类别优先级更高。不需要每条都评论，只报真实存在、能说清后果的问题。

## 1. 正确性（blocker / major）

- 改动是否真的实现了标题和描述说的目标；有没有漏改的调用方、配置或分支。
- 边界：空值、空数组、0、负数、超长输入、并发重复提交、网络失败、超时。
- 条件判断写反、`==` 和 `===` 混用、`||` 与 `??` 误用（0 和空串被当成缺省）。
- 异步：漏写 `await`、Promise 没处理 reject、竞态（后发的请求先返回把新数据覆盖）。
- 状态：重复回调、重复点击、页面返回后状态没重置、缓存没失效。
- 删除的代码是否还有地方在用。

## 2. 安全（blocker / major）

- 密钥、token、密码、内网地址硬编码进代码或提交了 `.env`。
- XSS：`v-html`、`innerHTML`、`dangerouslySetInnerHTML` 渲染了用户或接口可控的内容。
- 注入：SQL 字符串拼接、命令拼接、`eval`、`new Function`。
- 越权：接口只靠前端隐藏按钮做权限控制；用前端传来的 userId 查数据。
- 敏感信息写进日志、埋点或 URL 参数（手机号、身份证、token）。
- 跳转和回调地址没做白名单（开放重定向）。

## 3. 性能与稳定性（major / minor）

- 循环里发请求或查库（N+1）；大列表没分页、没虚拟滚动。
- 定时器、事件监听、订阅在组件卸载时没清理。
- 深层 watch、在模板里调用重计算函数、没必要的整对象响应式。
- 大图没压缩、资源没走 CDN、首屏同步加载了非首屏模块。
- 后端：事务范围过大、锁粒度、缺索引、未设超时的外部调用。

## 4. 可维护性（minor）

- 重复代码：项目里已有工具函数或组件却重写了一份。
- 魔法数字、硬编码的业务配置（活动时间、价格、开关）应进配置。
- 函数过长、职责混杂；命名和实际行为不一致。
- 注释和代码不符；遗留的 `console.log`、`debugger`、注释掉的大段代码、无主的 TODO。
- 改了接口或公共组件，但没同步类型定义和调用方。

## 5. 风格（nit）

只在和项目已有写法明显不一致时提，并且合并成一条，不要逐行刷。格式问题交给 lint，不写进评审。

## 前端 H5 额外关注

- 移动端适配：px 与 vw/rem 换算基准是否和项目一致；iOS 安全区；软键盘顶起布局。
- 兼容性：可选链、`Array.prototype.at` 等新语法在目标 WebView 上是否被转译。
- 埋点和渠道参数在跳转中是否丢失。
- 活动页：开始和结束时间的判断用服务端时间还是本地时间；活动结束后的兜底展示。

## Java 后端额外关注

- 空指针：`Optional`、集合判空、拆箱。
- 事务注解生效条件（同类内部调用不生效）、异常被吞掉。
- 接口入参校验、统一返回包装、错误码。
- 线程池、连接池参数，异步任务的异常处理。
