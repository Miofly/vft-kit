## 多任务并行（硬规则：速度和 token 兼顾）

- 请求含多件互不依赖的事（多个段落、文件、模块、平台、问题、调研方向），第一步就拆开并同时开干；不串行，不等用户说「开多个任务」。按子项大小选最便宜的并行方式：
  - 查找、读文件、几条命令：主控在同一条回复里并发多个工具调用，不开子 agent。
  - 测试、构建、下载、同步脚本等长跑：后台 Bash，主控继续干别的。
  - 要读改多个文件、预计超过约 10 次工具调用、或输出会大量灌进主上下文的子项：才开后台子 agent（每个启动约 50–70k token），并发上限约 8。
- 子 agent 任务书一次写全：主控已查到的事实（绝对路径、命令用法、结论、坑）必须写进去，不让子 agent 重新探索；写明目标、只能改的文件、备份位置、验收命令、能否提交。报告只要结论、改动行号、验收输出，20 行以内，直接回复。
- 查代码由主控用代码图工具（如 codegraph）直接做，不把纯查找委派给子 agent；子 agent 只接改动、测试、长跑的活。
- 同一文件不得有两个任务同时写：同一文件的多个子项由一个任务做，或各任务只返回改后文本、由主控一次合入；有先后依赖的（先写去处再删原处、先改源再同步）由主控排序。
- 子 agent 的模型交给模型路由 hook（如已装 claude-model-router-hook：机械活 haiku，其余用主模型），不手写 `model`；机械活的任务书写成按清单执行，便于路由到 haiku。主会话上下文很大时不用 `fork`（会带上整个上下文）。
