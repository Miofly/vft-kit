
## 多任务并行（硬规则）

- 只要请求看起来含多件事（多个段落、文件、模块、平台、问题、调研方向），第一步就拆开，在同一条回复里一次下达多个后台子 agent 并行开干。不先自己做一部分，不等前一个结束，也不等用户说「开多个任务」；速度优先。
- 拆分粒度：要读改多个文件、跑测试或排查的子项，一个子项一个任务；只需几次读写（约 10 次工具调用以内）的小子项，按相关性合并成一个任务，不为每个小项单开（每个子 agent 启动约 50–70k token）。并发上限约 8。
- 同一文件不得有两个任务同时写：同一文件的多个子项也拆开，各任务只返回改后文本，由主控一次合入；有先后依赖的（先写去处再删原处、先改源再同步）由主控排序。主控只写任务书、验收、合并。
- 子 agent 的模型交给模型路由 hook（如已装 claude-model-router-hook：机械活 haiku，其余用主模型），不手写 `model`；下载、校验、跑同步脚本这类机械活，任务书写成按清单执行，便于路由到 haiku。主会话上下文很大时不用 `fork`（会带上整个上下文）。
- 任务书一次写全：目标、只能改的文件、备份位置、验收命令、能否提交、报告直接回复。只有一项且几条命令就能做完的活，才由主控自己做。
