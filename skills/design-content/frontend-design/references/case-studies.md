# 三个案例：从整页结构提炼设计，而不是只抄 Hero

本轮直接浏览三个公开页面，查看桌面整页截图、390px 窄屏、计算样式、内容模块和部分未提交的交互入口。以下“观察”是源站当时表现，“迁移规范”是本 skill 的实现要求；不把源站的演示统计、评价或按钮当成真实业务能力。材质测量和 Taste 动效记录见本页末「参考站观察」。

## 教育平台：用课程任务组织玩趣风格

来源：<https://www.uupm.cc/demo/educational-platform>

### 观察到的整页组织

1. 浮起的导航容器：品牌、目录链接与主要注册操作；深墨描边、圆角和硬投影建立触感。
2. 首屏：左侧圆润大字与两个层级的 CTA，右侧是课程进度卡和贴纸；进度面板直接说明“学习可以继续”，不是无意义的仪表盘图。
3. 课程预览：四张课程卡形成两列，用题名、讲师、课时、时长、人数与评分支撑选择。规则一致便于比较，不应因为“重复卡片像模板”强行做成四种不同布局。
4. 学习利益：四张较柔和的说明卡，弱化硬墨投影，把表达从“可选课程”切换到“为什么在此学习”。
5. 学员证据：三张评价卡；再进入对比明显的蓝色报名区，以免费试用、价格和取消条件完成转化叙事，最后是分组页脚。

Fredoka 标题 / Nunito 正文形成圆润辨识度；主操作绿色、辅助浅蓝、粉紫绿贴纸形成有限调色板。课程和评价卡以深墨边框及零模糊偏移投影为主，不能称整页都是软黏土。

### 迁移规范

- 先确定真实课程字段和“浏览 → 选课 → 开始/继续学习”的状态链，再决定卡片尺寸。题名长、评分缺失、免费/付费、未报名、加载/错误都必须可表达。
- 字形圆润不等于每处都用超粗展示字；正文、数据和按钮保留清晰可读的层级。中文回退需与 Latin 标题一起核对。
- 桌面双栏中的进度演示到手机可以重排、压缩或作为后续说明，不应删除真实用户必须查看的进度信息。
- 在 390px 观察到正文居中、CTA 竖排、课程进入单列。导航与首屏徽标存在重叠风险：固定/浮动头部需预留实际高度，不复制遮挡。
- 本轮点击 `Browse Courses` 后 URL 与 `scrollY` 未改变，也未出现对话框。只可把它当视觉演示入口，不能据此宣称源站课程浏览链路已实现；本地复刻必须接真实目标或清楚标为演示。

## 宠物美容：摄影、服务比较与预约闭环

来源：<https://www.uupm.cc/demo/pet-grooming>

### 观察到的整页组织

1. 首屏暖橙 CTA、宠物照片、服务价格浮签与简短信誉数据，强调亲切、照料和可预约。
2. 六项服务以三列规则网格列出，每项包含图形、服务名、描述、起价与预约入口；照片图库接着展示六只宠物，先解释能力再给可视证据。
3. 三档套餐：Basic / Premium / Spa Deluxe；中间套餐以边框、徽标和实色按钮突出，其余保留较弱 CTA。内容仍可横向比较，不能用颜色作为唯一推荐标记。
4. 三张评价与统计条后，末尾两栏把便利条件和预约表单并置；用户不用在长页里寻找第二个流程。
5. 预约字段包括姓名、电话、宠物名、宠物类型、服务、日期和时间；页脚延续同一暖色厚度。

Nunito 标题 / Quicksand 正文、24px 白卡片、暖色低透明度偏移阴影与底部 inset，明显比教育站柔和。大图、自绘图标和浮签的比例，比单纯把主题色改橙更关键。

### 迁移规范

- 服务卡、套餐和预约表单共享同一服务 ID、价格与可用时段，不能三处写死不一致文案。点击某项预约后保留所选服务和套餐上下文。
- 图库图片先核实授权、尺寸和裁剪，不能把源站宠物/宠物主人评价冒充新商家的作品与客户。
- 预约需真实 label/input 关联、可访问名称、必填与格式校验、可用日期时间、价格条件、提交中/失败/成功、重复提交保护；不为视觉复刻删除这些状态。
- **源站边界**：本轮点击 Hero `Book Appointment` 后无导航、无弹窗，页面未滚到表单。表单虽可见，七个控件当时均无 `id`、`name`、关联 label，`required=false`。因此不能把“有表单外观”当作预约系统已完成，也不要复制其语义缺口。没有提交预约，未验证远端持久化。
- 390px 无页面横向溢出；窄屏导航按钮缺少可访问名称的观察应在复刻中修正，不因原站如此就保留。

## 奢侈品电商：摄影叙事是主体，玻璃只是局部材料

来源：<https://www.uupm.cc/demo/luxury-ecommerce>

### 观察到的整页组织

1. 固定轻玻璃导航覆盖大片场景摄影；标题用 Playfair Display 与局部斜体强调，正文 Inter。黑色主 CTA 与细边次级 CTA 保持克制层级。
2. 四件商品直接以大照片、品名、价格和少量 New/Exclusive 标签展示，没有给每件套厚重卡框。留白与对齐组织信息。
3. 工艺段落采用照片和正文两栏，局部玻璃铭牌承载历史数字；质量、热情、历久等品牌价值用三个小项补充，而不是再堆大卡片。
4. 三张横向系列摄影把商品扩成收藏体系；黑底会员段落反转全页明度，用少量黄色 CTA 和斜体强调独享感。
5. 邮件订阅和多列页脚作为低承诺延续路径。源站商品、历史、价格和会员权益均是案例内容，不当成真实商家事实。

观察到导航白色约 80% + `blur(12px)`，两处 `.liquid-glass` 白色约 70% + `blur(20px)` 与轻阴影。它是 web frosted glass，不是证明已经实现 Apple 原生 Liquid Glass 的折射、亮度或系统适应行为。

### 迁移规范

- 先选择高质量且授权清楚的产品与工艺摄影，设置固有比例、响应式裁剪和文字对比遮罩。不要把主要风格错误归结为“加 blur”。
- 商品展示与购买保持不同状态：点击卡片/Quick View、变体、库存、价格、购物车和付款语义需要真实接线；只复刻营销页时明确范围。
- 半透明区域在最复杂背景上检查对比；不支持 blur 或低端设备用不透明/半透明静态层，保留内容和层级。
- 390px 观察到商品单列约 342px 宽，Hero 标题 `48px / 60px`，历史玻璃牌隐藏、会员玻璃牌保留。手机排版重组而非等比缩小，不为保留浮签遮挡正文。
- 会员、订阅、购买未提交；不宣称邮箱已入库、会员已申请或结账成功。`href="#"`、无业务回执的按钮须在本地接线或标示演示。

## 跨案例可复用的构建顺序

1. **内容与任务骨架**：真实模块、字段、动作与转化顺序；先保证默认/空/错/加载可用。
2. **视觉系统**：角色色、字排、空间、边框/阴影/透明度的组合关系；同一风格可有明确变体，不贴单一标签。
3. **组件态**：卡片/按钮/表单/导航/弹层的默认、hover、focus、pressed、selected、disabled、pending；沿用项目已有组件语义。
4. **响应式重组**：内容优先级、列数、图片、浮签、头部安全间距、触控与软件键盘，不只缩放字号。
5. **动效**：强化本页的空间/状态关系，而不是给所有模块同一淡入。具体配方与组件实现见 [motion.md](motion.md)、[motion-components.md](motion-components.md)、[visual-effects.md](visual-effects.md)。
6. **验收**：看全页和真实任务链，键盘、窄屏、减少动效、长内容与错误态。源站的视觉优点可以采用，源站的无效按钮、缺 label 与遮挡不应复刻。

本轮是参考研究，不是三个商业业务系统的全功能测试；未复制整站源码、品牌照片、评价或账号数据。


## 参考站观察：风格不只看名称，动效不只看截图

观察日期：2026-10-27。以下是对公开页面的只读浏览器观察，不是本地生成页的质量评测，也不是源站全功能或移动端验收。案例图片、字体文件和整站源码未复制。

### Taste 展示页：叠卡切换

来源：<https://www.tasteskill.dev/>，关联仓库 <https://github.com/Leonxlnx/taste-skill>。

### 已观察到的行为

- Hero 左侧提供标题与操作，右侧用多张真实案例截图形成有纵深的卡片堆栈。点击 `Show the next example built with Taste Skill` 按钮更换前景案例，不是把整页做成幻灯片。
- 点击前截图与点击后截图的前景案例不同，背景保持稳定。卡片使用顶部变换原点，进出过程组合纵向位移、缩放和透明度。
- 本轮逐帧采样中，三张稳定可见卡片起点分别约为 `scale(1) / translateY(0)`、`scale(.94) / translateY(-25.44px)`、`scale(.88) / translateY(-50.88px)`；退场卡片短时放大至约 `1.03`、下移约 `32.7px` 并淡出，后层补位。
- 浏览器动画对象显示本次交互存在约 `240 / 450 / 550 / 650ms` 的多轨时长；滚动到下一展示区时观察到 `700ms` 的进入动画。这些是当次页面状态的测量，不是仓库中所有动效的默认参数。
- 动态模拟 `prefers-reduced-motion: reduce` 后，案例按钮仍可操作，页面仍报告 `200–300ms` 动画。仅据此不能判定所有运动均被禁用，也不能宣称已完整通过减少动效验收；需检查属性和位移，而不是只看时长。

### 复刻实施要求

复刻的是“可操作案例堆栈的空间关系和前后交接”，不是给所有卡片附加普通淡入：

1. 按卡片角色明确前景、后层和退场状态，先定义静态构图，再定义状态过渡。
2. 在每次切换时保持身份与层序稳定，明确快速重复点击是排队、合并还是忽略，不能让卡片永久透明或丢失焦点。
3. 将截图保留在固定比例容器内，移动与缩放不引起正文和操作按钮重排；避免过大的离屏图像和持续保留 `will-change`。
4. 用真实按钮、明确可访问名称和键盘触发；触屏不依赖 hover。图片说明反映案例内容，不复制源站图片冒充自己的作品。
5. 减少动效时保持相同最终卡片和可操作性，去掉大幅位移、缩放和回弹；可选择立即替换或短淡化。不能只把正常动画加速后称为无运动。
6. 验证前进/后退导航、组件卸载与重复进入后的状态；动效库按项目已有实现选，不因参考站使用某栈而强装。

具体配方与实现应继续读取 [motion.md](motion.md) 及其指定源文和模板，不能用本节观察替代核心规范。源站网页与固定版本技能库并非同一产物：未找到对应公开组件时，按上述可见行为重建并标明，不能声称逐字复用了源站组件。

### 本地可执行配方的浏览器检查

以同一配方 HTML/CSS 和模块源码注入 Chromium 的 `about:blank` 页面，未启动本地 HTTP 服务、构建或加载网络资源。模块原本的本地 import 改由测试注入，不能由此宣称正式站点加载链或产品集成已验证。

- 定稿叠卡：点击由第 1 张切到第 2 张，完成后仅一张活动语义卡且卡片动画数为 0；空格键切到第 3 张并保留按钮焦点。
- 动态设置减少动效后，切到第 4 张，媒体查询确认为 `true`，卡片动画数为 0。
- 窄屏模拟 `390×844`：页面 `scrollWidth=390`，没有横向溢出；按钮约 `116×53.59px`，活动卡片约 `358×288px`。这是模拟视口，不是真机。
- 卸载后移除增强态、各卡片 `aria-hidden` 恢复为无属性，说明文字恢复为“全部四个说明在上方”。
- 早期测试与文件修改并发，曾读到 native disabled 旧实现及尚未同步的测试断言；稳定文件后重新注入，以上交互与 Node 回归均通过。后续应在文件写锁释放后对定稿执行验收。
- 截图发现叠层上沿会遮到标题，已在增强态预留 `4rem` 顶部空间。修后按 `1280×844` 与 `390×844` 复测：最上层卡片距标题下沿均为 `16px`，页面无横向溢出。负向变换不占文档流，应为最大位移和阅读间距预留空间，不能只根据“按钮能点击”判视觉通过。

尚未验证 GSAP 场景的真实滚动与低端设备性能、完整屏幕阅读器或产品路由集成。原生开窗配方和第三方组件还需在目标项目分别验收。

### 验证边界

- 已做：公开页面读取、桌面截图、计算样式、Taste 点击切换与逐帧状态采样、一次动态减少动效设置观察。
- 未做：生成页对照、手机真机/窄屏验收、性能基准、完整无障碍审计、源站所有动画与业务流程验收。
- API 化边界：本次仅公开视觉观察，无认证业务写入，不涉及登录接口或远端业务 API 演进。
