# 主题、信息与布局：先有内容，再有风格

本参考融合 Taste 与 Frontend God Mode 的可迁移方法，许可见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)。Taste 不只是动画库：它包含主题构思、信息架构、图像、排版、布局与截图反馈循环。不把其 house style 当作所有项目的强制规范。

## 1. 先辨认做哪种界面

| 界面 | 首要任务 | 布局应服务什么 |
| --- | --- | --- |
| 营销、作品、产品展示页 | 读懂主张、看到证据、进入下一步 | 有主题的构图、真实图片或产品演示、段落节奏；需要时一个有记忆点的动作 |
| 仪表盘、管理、编辑、设置页 | 高频查找、比较、操作与恢复 | 稳定导航、合理密度、对齐数值、真实状态、可预测控件；重复行、卡片、边框完全可能正确 |
| 产品页里的应用片段 | 证明产品如何工作 | 内部沿用真实应用组件、数据与交互；外部裁剪服务展示页，不画灰条假后台 |

不要把营销页的大标题、超宽留白与滚动叙事套进每天使用的表单，也不要把后台拆成一屏屏广告海报。应用界面（外壳、KPI、图表、表格、表单设置、密度、状态、手机）读 [app-screens.md](app-screens.md)，仍以项目组件与业务规范为准。

## 2. 用主题事实产生一个设计命题

先找受众、主要任务、真实名称、产品约束、已有设计系统与可用素材。再列最能区别该对象的事实：产物、地点、材料、形状、使用仪式、工艺、票据/菜单/地图等已有视觉语言。资料不足时写明合理假设；不能伪造评价、客户、业绩与授权。

用一句话连接主题和构图：**“把这个对象特有的 X，变成页面的 Y。”** 例如真实路线可以组织时间线，真实成品可以组织作品索引；“高级、现代、干净”不是主题。将竞品名称替换进来仍完全成立，说明还停留在行业模板。

已有身份优先：用户要求、项目 design system/组件与无障碍约束 > 指定风格参考 > 风格库建议 > anti-template 启发。指定黏土、磨砂玻璃、奶油色、圆角或 Inter 时就认真实现它；不能用上游禁令擅自换风格。私有产品的已验证视觉基准由私有层提供，不被公共默认审美覆盖。

## 3. 先写信息结构，再比较构图

- 每个区域写“用户的问题 → 要表达的主张 → 证据 → 可做的事”。无任务的段落不为凑长度存在；需求里的完整信息不能为追求留白删除。
- 在既有 token 中确定颜色角色、字体角色、间距和密度；只为未定项作选择。保留真实字体资产、字重、中文覆盖、fallback 与加载策略。
- 对自由度高的展示页，用两三个简短线框比较：对象主导、排版主导、演示主导等；不是把多个风格混在一起。组件级修改直接服从周围，不必重做整页方案。
- 让每屏有明确主次。共享少数对齐线，段内近、段间远；检查空白是有意停顿还是短内容撑满视口留下的洞。不要强制所有 hero `min-height: 100dvh`。
- 展示页可用照片、索引、对比、列表、满幅与文字段落改变节奏，但不强制相邻模块永远不同；列表、商品、套餐和数据行的一致性往往正是可用性。
- 在手机上重新安排阅读顺序、换行、裁剪与操作位置，不只是等比缩小桌面。合法横向数据表或轮播应有清楚的可滚动提示、键盘路径与非截断内容；禁止的是意外页面溢出，不是一切横向滚动。

## 4. 真内容和图片是布局输入

1. 优先使用用户/项目已授权的素材、真实产品截图；再考虑与主题相符且许可已核实的公开素材。网络上可见不等于可再分发，仓库 MIT 不自动覆盖示例站照片、字体、品牌与肖像。
2. 选择前查看图片本身，核实来源页、作者、许可、必要署名和修改/商用限制；记录到项目已有资产清单。不得把别人的房间、团队、商品或界面冒充客户自有内容。
3. 给图片正确比例与固有尺寸，按桌面/手机分别检查 `object-fit`、`object-position` 或响应式裁剪；不能裁掉关键对象、拉伸照片或让文字落在无对比的背景上。
4. 用数据产生的真实界面证明软件能力；示例数据明确标注，不把“更像真的”小数或人物名包装成事实。错误、空、加载、最长标题与大数值都要有合理布局。
5. 素材缺失就调整构图或标注待替换项。无需满足固定“至少四张照片/一段视频”的数量；不为达标复制无授权图库。本集成不附完整 Taste 图片、案例站数据库，也不下载参考站源码。

## 5. Look → critique → fix：看结果，不看意图

已有页面先读 [style-migration.md](style-migration.md)，记录功能与视觉前态。浏览器仅在任务确实需要、且已有可用预览或得到启动授权时使用；修改技能文档不要求做一个无关示例页面。

- 首先 `command -v ego-browser`；有则遵循 `ego-browser` skill，以 ego-lite 独立 taskSpace 打印、复用 `spaceId`，最后 `task.finish({ keep: [] })`。仅不存在时才走 Playwright。无授权不启动服务、安装浏览器、构建或部署。
- 对桌面、窄屏与真实长内容看首屏和整页。先一秒辨焦点，五秒问“是什么、给谁、下一步”；再看主题辨识、层级、边缘对齐、空白、字体、配色、图片、段落节奏与内容完整性。
- 然后检查状态、焦点、菜单/弹窗、固定元素遮挡、意外溢出、图片加载、减少动效与原有业务路径。截图不能代替键盘与功能测试。
- 每轮只挑最影响用户的三个问题，写明截图/视口/状态、可见现象、修法，再看修后截图。通常一至三轮；卡住就报未解决项，不虚报分数或像素一致。
- 先修内容与概念，再修层级、构图、字/图、颜色，最后细节与动效。诊断模板迹象是问“这次为什么这样”，不是看到奶油色、Playfair、玻璃或重复卡片就扣分。

审查流程与评分口径以 [design-review.md](design-review.md) 为准；Awwwards 权重、照片数量、动效数量、硬性 house-style 扣分不是本地通用验收标准；无浏览器比较就标记视觉效果未验证。
