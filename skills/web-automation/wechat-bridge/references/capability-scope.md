# wechat-use 全能力对齐范围与验收

权威基准：[上游 capabilities.md](https://github.com/leeguooooo/wechat-use/blob/main/docs/capabilities.md)。2026-11-11 已在线读取；以具体 SDK 版本、微信 build、账号授权和验收结果为准，不能用截图上的亮点代替矩阵。

## 目标与复用原则

最终目标是覆盖上游当前公开支持的功能，不局限于发送 HTTP 协议。优先通过上游 CLI / daemon / SDK 的公开入口复用现有能力；自派生 profile 与实验 dylib 是独立的版本适配研究，不等于继承 SDK 的所有业务。

上游服务端激活、Keychain token、签名 profile 和版本前置条件保持原样，不绕过。当前上游文档指定微信 4.1.9 build 268596 / 268602；本机实验副本 4.2.0 build 270353 的登录和元对象派生成功，**不代表上游 SDK 已支持该版本**。没有经过运行验收的项统一标未验证。

## 文件传输助手单次界面发送验收（2026-11-11）

在获授权的 `WeChatSend` 副本内，通过 cua-driver 后台双击会话打开独立的「文件传输助手」窗口，核对窗口标题与空草稿后，以后台 `type_text` 写入唯一测试文本，再回读全文，最后仅按一次 Return。消息随后进入聊天记录，输入框清空，后续截图未见失败标记。未重启、未重新登录、未调用旧版 socket，也未向其他联系人发送。

验证边界：这是 **cua-driver 后台界面发送**，不是独立原生 Qt 发送器、HTTP `/send` 或上游 SDK 的端到端验收。只证明桌面发送侧聊天记录出现该消息；手机端独立接收、服务端回执及零焦点变化未单独验证。截图与回读证据保存在本机任务产物目录，不发布聊天内容。

可复用流程：不要把只有 `raise` 动作的 AX 控件等同于不能后台输入；单击工具返回成功也不代表已切会话。后台双击可能打开独立聊天窗口，须重新 `list_windows` 并绑定该窗口；写草稿后回读正文与收件人，发送一次后再次核对聊天记录，结果不明不得重发。

## 文件传输助手原生 Qt 与 HTTP 提交验收（2026-11-11）

两条唯一测试消息分别经原生 Qt 和 HTTP→exec→原生 Qt 提交，各只尝试一次。两次都在已运行副本的 GUI 主线程上，先校验 vtable、编辑器成员归属、`input+0x258` 的 `filehelper` 收件人、空草稿，再写入并逐 UTF-16 回读一致，调用 `Send` 局部 id 8/action 0，最后读取到草稿清空。LLDB 均已分离；没有重启、重登或覆盖进程已映射的 dylib。

- 原生测试 `QT-02`：Qt 返回值 2，状态 `submitted_unconfirmed`。
- HTTP 测试 `HTTP-QT-03`：POST `/send` 实际进入原生调用，耗时 11.86 秒，状态 `submitted_unconfirmed`；HTTP request_id `1794372878873-0`。原生回执另外持久保存在任务的私有 `native-receipts` 目录。
- 新执行器 `native_executor.py` 只接受精确 `filehelper`，绑定模块 SHA-256 与目标 pid/应用路径；每次重新只读定位，不缓存对象地址。以串行锁保护附着，发送前持久创建唯一正文 claim；重复正文和其他收件人真实运行时均被拒绝，没有新增提交。
- Qt 数据头为该 build 验证过的 Qt5 风格单指针布局（offset=24、ref=1），堆分配后使用该 build 的 QString 析构函数释放；这是限定 build 的实验构造，不是已验证真实字符串工厂或通用 Qt ABI。
- LLDB `expression --timeout` 单位是**微秒**；5 秒为 `5000000`。使用 SB API 时以 `SetTimeoutInMicroSeconds(5000000)` 设置，唯一 main-thread 检查，`finally` 分离。整个 LLDB 进程发生外部超时时仍须核对副本是否遗留暂停，不得把超时解释成未发送。

**发送侧补验已完成**：2026-11-11 后续后台截图 `recipient-nav-before.png` 同时显示 `QT-02`、`HTTP-QT-03` 和聊天 skill 的唯一测试正文，位于文件传输助手的发出消息气泡中，未见失败标记。与控件树回读一致。历史原生回执仍保留 `submitted_unconfirmed`，不篡改；这证明桌面发送侧聊天记录，不是手机端或服务端送达回执。手机接收仍未验证。

## 精确收件人扩展（默认不扩大发送范围）

- `wechat_probe.c` 新增可选 `RECIPIENT_OFFSET` 参数，在已核验偏移读取 libc++ 短/长字符串；校验容量、长度、结尾零、字符集与可读内存，最大 128 字节。超过输出候选上限也标 `bounded:true`，不能把截断结果当唯一。
- `native_executor.py` 新增 `op=resolve`（仅显式 `recipient_aliases` 与已配置 ID，不是完整通讯录）和 `op=preflight`（只读精确 wxid、编辑器归属匹配，不检查草稿、不声明 send_ready）。缺少精确字段时不退回全对象的 filehelper 子串命中。
- 发送支持私有 `allowed_recipients` 精确列表，缺省仍为 `["filehelper"]`；昵称映射不授予发送权限。主线程在写入前及提交前再次核对完整 wxid，支持短/长字符串，claim 键包含收件人且旧 filehelper 摘要不变。
- 真机只读通过文件传输助手正例、错误 ID 拒绝；后台打开另一现有聊天并读取到独立 ID，没有写草稿或发送，随后关闭临时聊天窗口。真实非 filehelper 发送与群聊未验。
- **导航仍未完成**：后台搜索输入可回读，但没有得到可靠搜索候选；单击会话没有打开正文，后台双击可打开独立窗口，必须重新绑定窗口、读原生身份。新文件助手窗口随后消失，对象释放，精确预检正确拒绝。原因未定，不重启、不强行附着旧对象、不自动补发。

## 上游 SDK 真机验收前置结果（2026-11-11）

指定 `--pid 98089 --bundle-id com.tencent.xinWeChat.send`，直接运行已按 BUILD-MANIFEST 校验的 1.19.22 CLI；没有安装、初始化、重启或发送。

- `auth status`：明确返回“尚未激活订阅”。
- `sessions --json --limit 3`、`contacts --json --limit 3`、`unread --json`：三项均真实运行，退出码 **2**，原因为缺少激活；没有得到查询数据，不能标通过。
- `doctor --json`：`all_ok:false`、`query_ready:false`、`send_ready:false`、`submission_ready:false`。还报告读取 config/key 缺失、daemon 未运行、`PythonCustody/AncestorWritable` 校验拒绝；不能因命令退出码 0 就报环境正常。
- `doctor --paths` 未识别数据库目录，但完整 `doctor` 和进程已打开的文件证明实际数据库位于副本的 `Data/Documents/xwechat_files/<account>/db_storage`；该项是路径探测差异，不是要求再次扫码。
- `daemon status`：退出码 1，`not running`。
- `disguise list`：退出码 0，主题枚举可用；只证明静态主题清单，不代表伪装与恢复已验收。

上述阻塞首先需要用户通过上游官方渠道取得有效激活，再核实该 SDK 是否支持当前 4.2.0。没有授权不能伪造 token/profile 或放宽校验。系统调试权限和 Python custody 修复须另列影响，不自动执行 sudo、重装或改共享环境。其余依赖授权、快照和后台服务的能力仍为**阻塞 / 未验证**，不能把拒绝执行当成业务功能通过。

## 验收顺序

1. **只读基线**：账号、build、后台进程、授权与可用能力盘点；不强杀、不重登、不扫描密钥文件内容、不导出聊天正文。
2. **发送链分阶段**：只读对象定位与归属校验，确认正确会话后先草稿再单次提交；未知状态停止重试。测试仅使用获授权的副本账号和文件传输助手。
3. **同账号查询**：联系人/会话/未读/成员、历史与搜索、统计/导出；一次验证一种真实数据契约。
4. **消息与媒体**：监听、结构化类型、@、引用、撤回边界、图片/文件/音频/朋友圈。
5. **统一入口**：HTTP/SSE、MCP、TUI、Wechaty、Hermes、多账号路由；外部 tunnel/webhook 需另行显式授权。
6. **生命周期**：冷启动、权限拒绝、版本漂移、失效/重连、升级回滚、停止与清理；逐项记录未验证项。

## 账号保护约束

- 本次授权测试对象是 `WeChatSend` 实验副本；主微信不动。测试消息仅发送文件传输助手，不能向当前选中的其他会话试发。
- 已登录后不得为调试擅自重启、覆盖已映射 dylib、重建签名或要求反复扫码。新增代码先离线测试，加载变更会影响运行态时单独说明。
- 未核实前不承诺不会触发平台风控，也不能把一次未登录探针不崩溃当成登录后发送安全。
- 截图/控件树必须绑定当前可见主窗口；旧登录窗口可作为隐藏窗口留存，不能据此断言掉线。
