# wechat-use 全能力对齐范围与验收

本地对齐基准：[v1.19.29 上游 capabilities.md](https://github.com/leeguooooo/wechat-use/blob/fcbe215d85645c121335b4a9f14e96324e9a9232/docs/capabilities.md)。公开 SDK 源码用于核对协议细节；上游文档、实验命令和本机实测结果分开记录。不能用截图上的亮点代替矩阵。

## 目标与实现原则

以公开能力表为对照，桌面界面路线默认使用已登录的主微信，不自动切前台或回退到副本；原生实验及上游兼容仍各自限于已授权的独立副本。下文副本记录只证明对应副本的分项结果，不证明主微信已通过。网页版文件传输助手、窗口可见标签和离线归档都不替代桌面原生能力；后台读取也不等于隐藏窗口可读。不要为本目标要求另扫网页版。上游 CLI / daemon / SDK 仅为可选兼容入口，其授权、组件测试和安装包校验不计入独立功能覆盖。

上游服务端激活、Keychain token、签名 profile 和版本前置条件保持原样，不绕过。当前上游文档指定微信 4.1.9 build 268596 / 268602；本机实验副本 4.2.0 build 270353 的登录和元对象派生成功，**不代表上游 SDK 已支持该版本**。没有经过运行验收的项统一标未验证。

## 主微信复验（2026-11-22）

- `desktop` 默认绑定 `com.tencent.xinWeChat`，不回退到副本，不置前；发送仅限精确核验的文件传输助手。主微信回执使用独立 `main` 子目录，旧副本保留原路径。Swift 自检、190 项桥协议回归及 4 项合成回执隔离检查通过。
- 真机开始时主微信在后台且主窗离屏，驱动报告 `ax_window_unresolved`；之后重查主窗在屏而应用仍在后台。此时 `--sessions-only` 跨 CLI、HTTP、MCP、终端读到 13 条可见会话名；文件助手 `probe` 核验了目标和空草稿，但 `--filehelper-only` 仍返回 `503`。发送预检与可见历史的业务判据不同，两者都不证明真实发送或送达；本次未写草稿、未发送。

## 独立结构化归档

`message_archive.py` 从显式 JSONL 构建单账号私有归档，支持时段历史、字面搜索、分组统计、分页 JSON / Markdown / HTML / CSV 导出、基线和按导入顺序补读。70 次跨进程 CLI 和 37 次实际回环 HTTP 请求通过（含本工具 JSON 导出跨库导回、归档 SSE 续读、空等待、鉴权及等待期间跨进程导入），包括同秒消息、迟到导入、重复、冲突整批回滚、按会话及自发消息过滤后续读、归档隔离、统计限量及鉴权。`by_hour_utc` 按 UTC 0–23 点给出完整小时分布，已核对整点、跨日、空结果、最大支持时间戳和 HTTP 一致性。分页导出固定首批记录范围，翻页期间新导入的记录不混入；跨归档或筛选条件的游标被拒绝。HTTP 查询与 CLI 结果一致，未改数据库字节；数据库缺失或权限不合格时返回 `503`，不伪造空结果。输入为合成数据；不计作微信全库或实时接收通过。
