# co-work-summary

基于本机开发活动生成指定时间段的工作总结。结果只能来自采集素材；证据不足时宁可省略，也不要补全或推测。

## 1. 适用边界

- 默认时间段为本周一到今天。
- 支持上周、本月、上月、某月第几周和明确起止日期。
- 用户已给出完整周报或月报，只要求润色、改写、翻译或排版时，直接处理现有内容，不运行采集脚本。
- 只在回复中输出总结，不创建、修改或发送任何文件。

## 2. 确定日期

将自然语言时间换算成包含首尾日期的 `YYYY-MM-DD`：

- 本周：本周一到今天。
- 上周：上周一到上周日。
- 本月：本月 1 日到今天。
- 上月：上月 1 日到最后一天。
- 某月第几周：按周一到周日的日历行计算，包含该月 1 日的周为第一周。例如 2026 年 7 月第四周是 2026-07-20 到 2026-07-26。
- 未写年份时使用当前年份；推算出的结束日期晚于今天时，先向用户确认。
- 前段时间、最近一阵等范围无法唯一确定时，先询问起止日期。

## 3. 采集素材

先确定本 `SKILL.md` 所在目录为 `<skill_dir>`，不要把用户当前工作目录当作技能目录。运行：

```bash
python3 "<skill_dir>/scripts/collect.py" --start YYYY-MM-DD --end YYYY-MM-DD
```

脚本默认扫描用户主目录。用户明确说明仓库位于其他根目录时，可重复增加：

```bash
--repo-root /absolute/path
```

脚本输出：

- A. Claude Code、Codex、Gemini 用户会话摘要。
- B. 按各仓库自身 Git 身份过滤的本人提交。
- C. 出现过活动的项目。
- D. 采集提示；出现这一段时，结果可能不完整。

脚本只读取本机数据并向终端输出，不创建或修改文件。

## 4. 归纳规则

读取 A、B 两段，按需求或项目合并重复内容：

- 同一需求的不同会话和提交合并为一项。
- 每项标题只写需求或项目名称，不添加括号标签。
- 子项以 `MM.DD 事实` 表示，只保留素材能够直接支持的工作。
- 提交、评审、走查、验证等节点只有在素材明确出现时才写。
- 删除问候、闲聊、环境探测和纯试验输入。
- 不把 D 段警告当作工作内容；如果警告可能影响完整性，在总结末尾用一句话提醒用户。

如果 A、B 都没有有效素材，直接说明指定区间内未采集到可确认的工作记录，不生成空项目或猜测内容。

## 5. 输出格式

标题必须匹配用户选择的时间段并包含日期范围，项目之间一定要有空行，展示更美观：

```markdown
### 上周工作（08.03 ~ 08.09）

- 项目或需求名称
  - 08.04 完成具体工作
  - 08.07 处理具体问题

- 项目或需求名称2
  - 08.05 完成具体工作
  - 08.06 处理具体问题
```

输出到此结束。除非用户另行明确要求，不追加计划、建议或后续动作。
