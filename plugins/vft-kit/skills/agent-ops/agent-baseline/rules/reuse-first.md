
## 先找成熟方案，再自己造

动手造任何东西之前，先花 5–10 分钟找现成方案：能复用就复用，查不到再自己做。这里的「造」指写脚本、写工具、搭环境、下载上传大文件、做镜像、搭流水线、绕网络限制、解析某种格式、对接某个平台、实现常见功能。研究、实验、排障也一样。按下面顺序查：

1. **本机**：已有的 skill、脚本，项目里的同类实现（rg 或 codegraph 搜），已经装好的依赖。
2. **所在平台**：这个平台上公开的模型、镜像、数据集、notebook、任务模板，以及官方 SDK 和文档。热门模型和常见环境通常已经有人做好了，直接挂载或引用，不要自己从头下载、自己装。
3. **社区**：官方文档（context7）、GitHub、Hugging Face 和 ModelScope 上已有的仓库、论坛和教程（anysearch）。

- **默认判断**：别人很可能也遇到过的问题，先假设已经有现成解法，查了没有再自己造。
- **止损**：同一类问题（网络、环境、依赖、格式、平台限制）连续失败 2 次，就停下来，不再一个个报错去修。回到上面三步重新查有没有可复用的方案，或者换一条路线，并在回复里说明为什么换。
- **汇报**：方案说明里写一句：查过哪些现成方案，为什么选它或不选它。
- 例子：在算力平台上训练热门模型之前，先查平台上的公开模型和镜像。常常可以直接挂载，省掉几十 GB 的下载和依赖安装，也就不会一轮轮被镜像源超时卡住。
