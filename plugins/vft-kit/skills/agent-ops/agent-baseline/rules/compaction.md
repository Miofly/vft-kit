
## 上下文压缩取舍

压缩、生成摘要或写交接文档时，逐个工具调用问两件事：

1. **调用本身还要记得吗**：这次调用的输入、做了什么、得出的结论，是否还影响下一步。
2. **输出还要原样保留吗**：只有内容仍然要用、且重跑一次拿不回来时才保留原文。

- **原样保留，不改写**：用户的约束和决定，架构决策及理由，原样报错，失败过的方案及原因，改过的文件路径，外部资源 id（任务、kernel、run、PR），有副作用的操作及其结果（写库、推送、部署、发布、发消息），验证状态，下一步。
- **只留一行「调用了什么 → 结论」**：Read、Grep、ls、查询、抓网页这类可重跑恢复的结果，需要时重跑。
- **丢弃**：无关探索、死胡同的中间步骤、已入 git 的文件内容、被后续结果覆盖的旧输出。
- 用户最初的需求和最近几轮不压缩。
