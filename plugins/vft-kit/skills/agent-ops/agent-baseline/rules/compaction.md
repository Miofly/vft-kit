
## 上下文压缩取舍

上下文压缩、写摘要或交接时逐个工具调用取舍；用户最初需求和最近几轮不压缩。
- **原样保留**：用户约束与决定、架构决策及理由、原样报错、失败方案及原因、改过的文件、外部资源 id、有副作用的操作及结果、验证状态、下一步。
- **只留一行「调用了什么 → 结论」**：Read、Grep、查询、抓网页等能重跑恢复的。
- **丢弃**：无关探索、死胡同、已入 git 的内容、被覆盖的旧输出。

### 什么时候交接（阶段切换表）

| 切换点 | 交接？ | 理由 |
|---|---|---|
| 调研 → 实施、方案定稿 → 动手 | 是 | 调研上下文体积大，结论已落到文档或任务书 |
| 调试完 → 下一个功能 | 是 | 排障痕迹会干扰无关的新工作 |
| 一条路线失败、准备换路线 | 是 | 先清掉死胡同里的推理，失败原因写进交接 |
| 实施中途 | 否 | 变量名、文件路径、半成品状态丢了代价大；做完当前一步再交接 |

上下文到约 40% 且正好处在「是」的切换点时立刻交接；落在「否」时先做完当前一步。
