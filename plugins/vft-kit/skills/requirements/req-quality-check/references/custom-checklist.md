# 业务自定义检查表

来源：需求质量检查表 v1.0 - Sheet3「自定义质量检查表」

> **说明**：本检查表为业务特有的质量检测项，支持动态扩展。
> 检查结果分三类：**已提供** / **未提供** / **不需要**
> 适用领域标注：通用 = 所有需求适用；前端 = 前端/App需求重点关注；后端/服务端 = 后端需求重点关注

---

## 零、需求文档完整性

> 来源：《团队需求规范》——项目需求文档必须包含如下内容

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 需求名称规范 | 需求命名是否规范，迭代类需求建议包含：渠道-业务方向-模块-优化点，并有版本号管理（如 V2.3）；实验类需求需注明【实验】 | 通用 |
| 需求背景&价值&目标 | 是否说明：1）业务背景和需求价值；2）数据分析依据及预期效果；3）要解决的问题和采取的改动 | 通用 |
| 交互设计完整性 | 1）是否有整体流程图或逻辑/玩法说明；2）是否有完整原型稿（贴入正文或附件并注明）；3）若有配置需求，是否包含管理系统相关交互需求 | 通用 |
| 渠道或主题信息 | 1）产品需求：明确本次修改覆盖哪些主题或渠道（渠道未确认前需保证有通用需求）；2）运营需求：明确修改哪些专题页/组件化页面及上线渠道；3）涉及厂商时需包含渠道对应的特性说明 | 前端 |
| 埋点需求 | 1）评审时是否已提数据需求说明；2）评审后是否提供埋点文档地址并贴到需求正文 | 前端 |
| 设计稿地址 | 设计稿验收通过后是否已将设计稿地址贴入需求正文。**特殊情形**：若需求正文本身即为设计稿链接（蓝湖/Figma等），视为已提供，但需额外检查：1）链接是否可正常访问；2）设计稿是否已通过验收（可从需求状态或备注判断） | 前端 |
| 计划实验周期 | 实验类需求必填：是否明确计划实验时长 | 通用 |
| 其他补充信息 | 是否补充：1）上线时间要求及原因；2）特效或交互效果视频示例；3）外部依赖的接口文档或其他研发所需信息 | 通用 |

## 二、非功能性需求

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 性能 | 如面向用户前端页面或运营系统交互响应延迟时间，后端接口请求响应时间、可承载的最大用户并发数等<br>**稳定性补充**：针对活动、批量推送性质需求，需要考虑集中并发等性能问题，产品需求需要说明性能指标要求（如预期并发量、峰值QPS、响应时间要求等） | 通用 |
| 兼容性 | 前端页面或web运营系统需要指明兼容的浏览器范围或内核版本（如微信浏览器、主流厂商自带浏览器等）；app应用需要指定适配的机型范围或操作系统版本（如支持Android6.0及以上等） | 前端 |
| 安全性 | 前端应用是否存在用户敏感信息加密传输存储的需求，web运营系统是否需要集成企业身份登录，限制内网或ip白名单等<br>**内容安全补充**：如果需求提到内容生产相关，需要考虑内容授权版权问题和UGC内容审核问题（如版权来源说明、授权协议、内容审核机制、违规内容处理流程等） | 通用 |
| 合规限制 | 相关功能是否存在法律法规和用户投诉方面的风险，如果存在是否提供相关解决方案？如客户端获取用户信息、开通计费业务等，是否明确提示用户或要求用户同意相关协议等 | 前端 |

## 三、通用业务场景

### 3.1 典型功能性需求

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 运营系统任务处理 | 1）设计页面交互需要考虑运营提供创建任务的原材料（视频文件、excel任务信息等）可能存在错误，如何校验错误，如何在交互上引导和提示运营修正错误？<br>2）任务设计需要包含主任务和子任务两个页面，在主任务页面展示必要的处理统计数据（成功、失败数量），以及展示任务处理的汇总错误描述；子任务页面需要展示任务处理详情和相关结果，并可展示单个处理结果，如失败可显示失败原因，由运营自助处理解决<br>3）从效率方面考虑，任何的任务处理都需要评估是否需要支持单个新增、批量新增和修改等操作 | 后端/服务端 |
| 任务（或资源）状态流转 | 1）针对状态较多且变化逻辑较为复杂的状态流转，产品需要提供相应的状态图，状态之间的切换逻辑需要结合原型具体交互或业务处理逻辑 | 通用 |
| 资源按用户状态过滤 | 页面涉及**音频/视频信息展示**时（专题、运营活动、推广页面、组件化页面等各类场景），需求需说明是否要根据**用户状态**（如会员/非会员、已订购/未订购、地域/运营商、收费与否等）对展示资源做过滤；缺失即报（优先级建议：🟡 中级） | 通用 |
| 是否需要埋点 | 需求需明确说明本次功能**是否需要埋点统计**；需要则应点出**核心统计诉求或关键点位**（如曝光、点击、订购转化等，不含具体埋点方案文档——方案由数据团队约定）。仅缺失「是否需要埋点」的说明即报；不因缺少埋点方案文档而报（优先级建议：🟡 中级） | 通用 |

### 3.2 APP（接口）版本升级兼容

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| APP（接口）版本升级兼容 | 1）后端接口服务升级针对老版本app是否存在兼容问题，如果存在是否提供相应交互逻辑？例如新增推送消息类型在老版本如何展示，收费铃声针对不支持收费的老版本接口层进行资源过滤<br>2）APP新老版本覆盖升级是否存在兼容问题？一般指用户存储本地的数据在新版本不兼容的处理逻辑，如用户缓存本地的铃声数据、主题皮肤等 | 通用 |

### 3.11 AB实验设计

> 适用于 AB/AA 实验类需求（各业务形态：组件化、移动端音频、H5视频等均可能出现）。判定为实验类（需求名含【实验】或说明实验分组/放量）时执行。

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 实验变量单一性 | 实验须遵循**单一变量控制原则**：实验组相对对照组只改动**一个变量**（如仅改文案、或仅改样式、或仅改交互路径之一），以保证数据可归因到具体变量。若需求一次改动**多个变量**，须说明是否拆分为多组独立实验、或采用多因子实验设计并明确各组差异与归因方式；否则多变量混杂将导致**数据无法评估由哪个变量产生**。存在多变量混杂且未说明拆分/归因方案即报（优先级建议：🔴 高，直接影响实验结论的可评估性） | 通用（实验类适用） |

## 四、常见异常场景

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 网络异常 | 1）网络无法连接的情况，是否提供相应的交互和提示语<br>2）网络加载缓慢出现超时情况，是否提供加载动画和加载失败提示页 | 前端 |
| 第三方中断 | 1）系统切换后台、电话和闹铃等系统中断操作，针对app如何给予响应，对于正在进行的操作如何处理，如音乐播放是否继续后台播放等？ | 前端 |
| 接口（三方服务）功能异常 | 1）前端应用在使用内部接口（或外部云端服务等）过程中可能出现的业务逻辑异常，如后端服务返回服务不可用之类错误，前端应如何提示用户？ | 前端 |
| 系统权限问题 | 1）APP调用系统部分功能时需要获得权限，如通讯录、相机和存储等，获取权限的交互提示是否补充？如用户未提供相应权限功能如何展现和提示交互是否补充？ | 前端 |
| 搜索排序 | 1）搜索排序相关需求，是否考虑运营提供创建任务的原材料（视频文件、excel任务信息等）可能存在错误，如何在交互上引导和提示运营修正错误？ | 后端/服务端 |
| 页面显示异常 | 1）页面上的文案或页面元素（如名称、描述、标签等）较长超过一行或超过固定区域时如何处理？<br>2）小屏幕手机兼容：页面或弹框会不会显示不全，此时如何处理？ | 前端 |
| 第三方渠道限制 | 1）页面内若有跳转到其他域名的页面，需要和渠道确认是否有域名限制，可自由跳转还是需要配置白名单<br>2）页面上若有调起其他第三方应用的交互，需要和渠道确认是否有拦截限制 | 前端 |

## 五、监控和统计需求

| 检查项 | 检查内容 | 适用领域 |
|--------|----------|----------|
| 业务异常监控 | 1）关键业务操作成功率统计监控，一般指的是存在外部不可控因素导致的业务错误监控，如数字内容业务开通、资源试听和短信发送成功率等<br>2）关键任务延迟处理监控，一般指的是因为短时的流量激增或外部因素导致的任务处理及时性存在问题 | 后端/服务端 |
| 资源不足监控 | 1）一般指的是和运营相关的一些指标性数据监控，如栏目配置资源因资源变更且运营未及时调整导致的资源不足，如活动中的奖品池数据 | 后端/服务端 |
| 关键指标数据统计反馈 | 1）一般指的是影响业务收入的一些关键性指标数据，如用户活跃度、业务新增订购数和业务收入等数据 | 后端/服务端 |
| 运营相关指标数据监控 | 1）运营待处理任务数据监控，一般指的是用于及时告知运营需要及时干预和处理<br>2）生成运营策略需要的相关统计数据，一般指的是根据现有数据情况生成相关报表告知运营及时调整策略 | 后端/服务端 |
| 前端用户埋点 | 1）需求中是否包含埋点需求说明（评审时提数据需求）；2）是否提供或计划提供埋点文档地址（评审后贴入需求正文）；3）是否有基于埋点数据生成报表的需求 | 前端 |

## 扩展说明

本检查表支持动态扩展。如需新增检查点，请按以下格式追加到对应分类：

```markdown
| 新检查项名称 | 检查内容描述（可包含多个子项，用<br>分隔） | 适用领域（通用/前端/后端/服务端） |
```

新增检查点将在下次检查时自动纳入评估范围。
