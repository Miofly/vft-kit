# 定时任务类需求专项检查

基于历史需求评审问题提炼的定时任务专项检查点，配合通用检查（req-quality-check）使用。

## 执行说明

1. 先通读需求文档，理解任务的处理目标和数据流向
2. **逐张读取需求中的图片**（流程图、数据流图、字段映射表、Cron 配置截图、状态流转图等），用 Read 工具识别其中的触发规则、数据范围、过滤条件、字段映射、异常处理、监控告警等信息。**定时任务的执行频率、数据范围、字段对应关系经常以表格或流程图形式给出**，必须把图片信息纳入下方各项检查；仅依据正文文字判断"未提及"会误判为缺失
3. 按以下各维度逐项检查，结合实际需求判断是否适用
4. 检查结果标记：✅已提供 / ❌未提供（需补充）/ ➖不适用（说明原因）
5. 最后加载 `references/custom-checklist.md` 中的定时任务自定义检查项，一并执行

## 输出规则（与 req-review-agent 编排时遵守）

- **只输出有问题的检查项**：✅已提供 和 ➖不适用 的项一律不展示
- **去重**：本专项检查只关注定时任务独有的检查点；通用业务场景已由 req-quality-check 业务检查表覆盖，本节不重复输出
- 若所有检查项均通过或不适用 → 整节不输出
- 直接给事实和建议，不写套话

## 内置检查点

### 一、触发规则
| 检查项 | 检查内容 |
|--------|---------|
| 触发方式 | 触发方式是否明确（定时触发/事件触发/手动触发） |
| 执行频率 | Cron 表达式或执行频率是否定义 |
| 执行时间窗口 | 执行时间是否避开业务高峰期 |
| 手动触发 | 是否支持手动触发，入口在哪里 |

### 二、数据范围
| 检查项 | 检查内容 |
|--------|---------|
| 全量/增量 | 每次处理的数据范围是否明确（全量/增量） |
| 增量基准 | 增量任务的起始时间/游标基准是否说明 |
| 数据量级 | 预估处理数据量级是否提供（影响性能评估） |
| 数据来源 | 数据来源（表/接口/文件）是否明确 |

### 三、幂等性
| 检查项 | 检查内容 |
|--------|---------|
| 重复执行安全 | 任务重复执行是否幂等（不会产生重复数据） |
| 幂等判断依据 | 幂等性的判断字段/逻辑是否说明 |

### 四、并发控制
| 检查项 | 检查内容 |
|--------|---------|
| 并发执行 | 是否允许多实例并发执行 |
| 防重机制 | 防止重复执行的机制是否说明（分布式锁/状态标记） |
| 锁超时 | 分布式锁的超时时间是否合理 |

### 五、失败处理
| 检查项 | 检查内容 |
|--------|---------|
| 重试策略 | 失败后的重试次数和重试间隔是否定义 |
| 重试耗尽 | 重试全部耗尽后的告警方式是否说明 |
| 部分失败 | 批次中部分记录失败时的处理逻辑（跳过/暂停/回滚） |
| 失败记录 | 失败记录的存储和后续人工处理方案 |

### 六、超时控制
| 检查项 | 检查内容 |
|--------|---------|
| 最大执行时长 | 任务最大执行时长是否定义 |
| 超时处理 | 超时后的处理方式（强制终止/告警/自动续期） |

### 七、监控与告警
| 检查项 | 检查内容 |
|--------|---------|
| 监控指标 | 任务执行结果的监控指标是否定义（成功率/处理数量/耗时） |
| 告警接收人 | 异常告警的接收人和通知方式 |
| 日志保留 | 任务执行日志的保留策略（时间/条数） |
| 执行报告 | 是否需要生成执行结果报告 |

### 八、回滚与补跑
| 检查项 | 检查内容 |
|--------|---------|
| 数据回滚 | 任务执行错误时的数据回滚方案 |
| 手动补跑 | 是否支持指定时间范围的手动补跑 |
| 补跑入口 | 补跑操作的触发入口和操作权限 |

## 输出格式

以**问题驱动**方式输出本专项检出的问题（**不使用表格**），供 `req-review-agent` 汇入统一「问题清单」。单独使用时追加在通用检查报告之后。

- 只输出有问题的检查项；✅已提供、➖不适用一律不展示；无问题则整节省略。
- 每条问题：来源统一标 **📋知识库(定时任务专项)**，置信度 高/中/低，含 原文/现状、问题、建议改写。

```
---

## 定时任务专项检查结果（仅列有问题项）

**[问题一句话标题]**　📋知识库(定时任务专项) ｜ 触发规则 ｜ 优先级:🔴 ｜ 置信度:高
- **原文/现状**：[引用原文 或 "未提及"]
- **问题**：[具体问题 + 触发条件/影响]
- **建议改写**：[可落地补充/改写话术]
```
