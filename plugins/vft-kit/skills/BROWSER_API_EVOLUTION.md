# 浏览器到 API 强制演进

适用于本 skill 中所有远端业务动作。登录、验证码、2FA 与纯视觉验收可以保留浏览器；认证后的业务读写仍按下列规则演进。

1. 执行前先查本 skill 的已确认接口与脚本；已有真实写入和回读证据的步骤必须直接调用 API，不得默认退回 UI。
2. 未知步骤只允许在同一登录会话中用 UI 探索；操作前开启网络事件、HAR 或 trace，记录 `method + path + body schema + status`、必要的 CSRF/签名语义，禁止记录 cookie、token、密码和无关个人数据。
3. 从页面请求、前端源码或官方文档确认接口后，在当前授权目标上直接复现；写前先读状态，避免重复创建、发布、提交或删除。
4. 写入成功后必须用独立读取接口或重新加载后的服务端状态回验；HTTP 200、toast、按钮消失或 UI 点击成功都不算业务完成。
5. 接口失败或尚未确认时才允许 UI 兜底，并记录失败端点、状态码、缺失字段和下一步；UI 成功不能标记为“API 已完成”。
6. 获得一次“API 写入 + 独立回读”证据后，同一任务内更新本 skill 的接口清单、默认路径和已有 helper；有分支/解析逻辑时补一个最小自检。下次必须 API 优先，不等待用户再次提醒。
7. skill 自更新只写方法、路径、字段语义、幂等条件与验证方法；示例值脱敏，凭据继续来自既有安全存储。
